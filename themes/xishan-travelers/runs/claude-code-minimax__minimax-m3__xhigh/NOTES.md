# 溪山行旅图 · 程序化水墨重建

## 做了什么

用 HTML5 Canvas 2D 程序化重建范宽《溪山行旅图》的核心意象。整幅画没有任何外部素材（无图片、无模型、无 HDRI），所有几何与纹理都是用代码生成。打开页面后立即可见完整画面，并循环播放四幕动画。

### 画面构成

- **绢本底色**：暖黄褐色 (#C1A26E) 衬底，带噪声织纹与边角暗角
- **远山**：左下与右下两抹淡淡的远山轮廓，仅以淡墨勾勒
- **主峰**：占据画面 2/3 高度，手调控制点构成的巨碑式山形
  - 内部上深下浅的渐变，左侧偏亮、右侧偏暗
  - 三层皴法（短雨点皴约 5000 笔、长曲线皴约 700 笔、苔点约 500 颗），用 FBM 噪声控制密度分布，自然形成疏密斑块
  - 顶部的"范宽式"密集苔点丛——先画径向渐变底，再叠稠密小圆斑与细枝条
  - 右侧一道细黑裂缝为瀑布崖口
- **云气**：主峰脚下与远山之间一道横贯的留白（米色绢面），加上半透明白色横纹模拟雾带
- **中景树林**：右半幅密集林木（用树簇函数生成），藏一座歇山顶小寺院
- **溪径与驮队**：底部溪流波浪线 + 蜿蜒土路；驮队由 2 人 4 骡组成，按进度从右向左行进
- **前景巨石**：四块有明暗渐变与皴法纹理的山石
- **落款**：第四幕末尾"范宽"二字与朱文印章淡入

### 四幕循环动画（总长 36 秒，每幕 9 秒）

| 幕 | 名称 | 内容 |
|----|------|------|
| 1 | 晨雾 | 山脚雾带渐淡，主峰从云中显现，瀑布自崖口开始下泄 |
| 2 | 行旅 | 骡队自画面右侧林间出现，沿溪径向左行进 |
| 3 | 钟声 | 寺院方向泛起一圈淡墨钟波，林中飞鸟惊起；后行者停顿片刻再追 |
| 4 | 入山 | 骡队继续向左消失于山脚，雾带重新聚拢，落款"范宽"与印章淡入 |

## 用了哪些技术

- **HTML5 Canvas 2D** — 全部绘制都在 `<canvas>` 上完成
- **离屏预渲染** — 所有静态图层（远山、主峰、树林、溪径、岩石）先画到一块 600×1200 的离屏 canvas，动画层再每帧合成到主画布，性能稳定
- **DPR 适配** — 主画布按 `devicePixelRatio` 缩放，移动端不会糊
- **CSS `aspect-ratio: 1/2`** — 保持原画竖长比例，三种 iframe 尺寸下都铺满可视区
- **种子伪随机（Mulberry32）** — 同一棵树在每次刷新后形态完全一致
- **Value noise + FBM** — 织纹、雾、云、笔触疏密都由分数布朗运动噪声驱动
- **二次贝塞尔曲线** — 笔锋、烟雾都用 quadraticCurveTo 模拟手绘抖动
- **径向渐变** — 岩石明暗、苔点底色、雾团柔边
- **中文字体栈** — `STKaiti, KaiTi, FangSong, serif`，直接走系统字体，无外部网络字体

## 怎么操作

- **桌面**：鼠标可以点击画面触发一次"钟声"波纹（额外彩蛋，不影响主循环）
- **手机**：竖屏时画面自动适配为 390×844；可以单指触摸，触屏的 tap 同样会触发钟波
- **键盘**：`Space` 暂停/继续；`R` 立即跳到本幕开始
- **被动播放**：不操作也会按 36 秒一轮自动循环

## 已知问题

- 皴法虽然在 FBM 噪声控制下有疏密变化，整体仍偏向"雨点皴"，与原画"芝麻皴"还有差距；如果想再逼真需要按不同山面方向再分层控制笔触角度
- 前景山石的轮廓还是略显几何化，缺乏真正的岩石转折感
- 落款是用代码一笔一笔画的近似字形，不是书法字体，仅作示意
- 主峰左下角与右下角的对称呼应略硬，远山云气之间还有改进空间
- 帧率在低端机（特别是大尺寸 iframe + 高 DPR）下偶有波动；静态层已离屏，瓶颈在每帧的动画合成（云、雾、瀑布、鸟、驮队）
